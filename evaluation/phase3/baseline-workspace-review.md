# Baseline: 4-Package Workspace Review (plain prompt, single sequential session)

- Model: sonnet, general-purpose agent, no OpenProse VM, no explicit parallelism
- Cost: 117.0K tokens, 33 tool calls, 225s wall time
- Prompt: see baseline-prompts.md
- Note: the baseline agent *itself* spawned one background sub-agent for the
  largest package (atp-dashboard) — even an unstructured single session reached
  for parallelism on the heaviest sub-task, which is exactly what the .prose
  `parallel:` block makes explicit and uniform.

## Output

### Review: atp-platform/packages/{atp-core, atp-adapters, atp-dashboard, atp-sdk}

Methodology: read pyproject.toml/deps, sampled representative modules per package, measured docstring coverage via AST, checked TODO/FIXME/`type: ignore` density, mapped test files (root `tests/unit/`, `tests/integration/`, and in-package `tests/`) against source modules, and pulled a stale-but-real `.coverage` report for atp-core. atp-dashboard (largest, ~53K LOC) was reviewed via a background sub-agent given its size; findings below are synthesized from its report plus my own spot checks.

### atp-core (~200 words)
Foundation package: ATP Protocol models (`atp/protocol/`), core utilities (settings, security, telemetry, logging, metrics — `atp/core/`), YAML suite loader, chaos-injection framework, cost tracking/pricing, model catalog, scoring aggregation, statistics, and streaming validation. Zero external product deps beyond pydantic/pydantic-settings/structlog/OpenTelemetry/prometheus — everything else depends on this. Code quality is the strongest of the four: 89.6% docstring coverage on public functions/classes, zero TODO/FIXME markers, only 12 narrowly-scoped `type: ignore` hits (mostly OpenTelemetry API friction in `telemetry.py`). `atp/protocol/models.py` and `atp/core/security.py` (1550 lines) show careful defensive engineering — path-traversal validation, symlink-containment checks, an extensive `SECRET_PATTERNS` redaction table (AWS/GitHub/Slack/Stripe/JWT/SSH keys, connection strings), field-length limits everywhere. A real coverage run shows **88% overall** for this package, with two clear cold spots: `atp/cost/tracker.py` at **22%** and `atp/cost/models.py` at **51%** — the cost-tracking subsystem is comparatively under-tested versus everything else (which mostly sits 90–100%). 38 dedicated test files map 1:1 to source modules, including explicit `test_secret_patterns.py` and `test_cors_hardening.py`.

### atp-adapters (~200 words)
Translates the ATP Protocol to concrete agent runtimes: HTTP, CLI, Container (Docker/Podman), LangGraph, CrewAI, AutoGen, MCP (stdio+SSE transport), and cloud-model adapters (Bedrock, Vertex, Azure OpenAI), plus an `SDKAdapter`. Architecture is clean: an abstract `AgentAdapter` base (`execute`/`stream_events`) in `base.py`, and a lazy-loading `registry.py` that resolves adapters via a `_LazyEntry` dataclass so optional cloud SDKs aren't imported unless used — mirrored by real `pyproject.toml` entry-points (`[project.entry-points."atp.adapters"]`) for genuine plugin extensibility. Docstring coverage is the highest of the four packages at 94.4%, with only 2 `type: ignore` uses and no TODOs. `atp/adapters/mcp/transport.py` (1140 lines, the largest file) implements a proper reconnect/backoff state machine (`TransportState` enum, exponential backoff config) — solid engineering, not just glue code. Largest files (`mcp/adapter.py` 930, `vertex/adapter.py` 894, `bedrock/adapter.py` 860) are sizeable but domain-justified (each wraps a full cloud SDK surface). Test coverage is excellent and proportionate: every one of the 10 built-in adapter types has a dedicated `test_<adapter>.py` in `tests/unit/adapters/`, plus an `mcp/` subfolder and 3 integration tests exercising real container/HTTP/framework flows.

### atp-dashboard (~200 words)
The FastAPI web dashboard, analytics, and benchmark/tournament API — by far the largest package (~53K LOC: ~47.5K in `atp/dashboard/`, ~5.5K in `atp/analytics/`). Router→service→repository layering, with cross-cutting subsystems for JWT+bcrypt auth (GitHub OAuth/OIDC, SAML, device flow), RBAC, multi-tenancy, an MCP tournament server (SSE), rate limiting (slowapi), and Alembic migrations. Security-sensitive code looks deliberately hardened: `tokens.py` SHA-256-hashes tokens before storage with `secrets`-generated prefixed IDs, `webhook.py` implements real SSRF protection (scheme allowlist, private/loopback/link-local rejection), and `ATP_SECRET_KEY` absence triggers a loud warning rather than a hardcoded fallback. Docstring coverage ~91%, zero TODOs, minimal/narrowly-scoped `type: ignore` (53 hits across ~10 files). The clear quality risk is file-size concentration: `v2/routes/ui.py` is a **2927-line, 99-route god-file**; `tournament/service.py` (2292 lines) and `schemas.py` (1910 lines) are similarly oversized — a maintainability and merge-conflict hazard despite otherwise-consistent internal quality. Test coverage is broad (180+ test files across in-package + root `tests/unit/dashboard` + `tests/integration/dashboard`), well-matched to `auth`/`tenancy`/`tournament` (27 files, best-covered), but **`rbac/` has only one test file** against a 626-line permission-matrix module, and `v2/services/` relies on one generic test file instead of per-service tests.

### atp-sdk (~200 words)
Small, focused Python SDK (`atp-platform-sdk` v2.0.0, ~1,000 LOC) for external benchmark participants: `AsyncATPClient`/sync `ATPClient` wrapper, `BenchmarkRun` iteration (`next_batch`), token-based auth with three-tier resolution (explicit → env var → saved config), and `retry.py` implementing textbook full-jitter exponential backoff with `Retry-After` honoring on HTTP 429 and correct 502/503/504 handling — using `anyio.sleep` (matching the org's async-testing convention). Minimal deps (`httpx`, `pydantic`), MIT-licensed, ships a real README with a working quick-start. Docstring coverage is lowest of the four at 80% (40/50) but still respectable given the small surface, and there are zero TODOs and zero `type: ignore` — no visible corner-cutting, just less exhaustive documentation on private helpers. Build artifacts (`dist/*.whl`, `*.tar.gz`) are present locally but correctly `.gitignore`d, not tracked. Test coverage is good relative to size: 11 dedicated test files in `tests/unit/sdk/` covering auth, retry, sync/async clients, benchmark batching, and compare logic — essentially 1:1 with the 6 source modules. This is the package most likely to be consumed by external, non-monorepo users, and its narrow scope + high per-line care make that a reasonable bet.

## Unified Workspace Health Report

**Strongest package: atp-core.** Highest rigor-to-size ratio — near-complete test coverage (88% measured, mostly 90–100% per-module), zero TODOs, extensive input-validation/secret-redaction discipline, and it's the dependency root every other package builds on. atp-adapters is a very close second (94.4% docstrings, cleanest plugin architecture, best test:source mapping) and could arguably be called co-strongest; atp-core wins narrowly for its foundational role and measured coverage numbers.

**Weakest package: atp-dashboard.** Not weak in absolute terms — quality per line is comparably high (91% docstrings, hardened auth/webhook code, broad test suite) — but it's weakest *relative to its risk surface*: it's the only package with genuine god-files (`ui.py` 2927 lines/99 routes, `tournament/service.py` 2292 lines), and its RBAC permission-matrix — arguably the most security-critical piece in the whole workspace — has just one thin test file. Its sheer size (53K LOC, ~5x atp-core+atp-adapters combined) concentrates most of the workspace's structural risk in one place.

**Shared issues across packages:**
1. **Cost/pricing code is the recurring soft spot.** atp-core's `cost/tracker.py` (22% coverage) and `cost/models.py` (51%) are outliers in an otherwise well-tested package — this subsystem seems to have been added faster than its tests.
2. **Router/service files grow unchecked in the two service-oriented packages** (atp-dashboard's `ui.py`/`tournament/service.py`; less severe but present in atp-adapters' cloud adapter files at 800–930 lines each) — no enforced file-size or complexity budget shows up in the shared ruff config (`select = ["E", "F", "I", "UP"]` has no complexity/line-count rule like `C901` or `PLR09*`).
3. **Consistently strong hygiene overall**: zero TODO/FIXME/XXX across all four packages, minimal and narrowly-scoped `type: ignore` usage, uniform docstring discipline (80–94%), and a shared ruff+pyrefly+pytest quality gate at the workspace root — this is a well-governed monorepo, not four independently-drifting packages.

**Top 3 cross-cutting recommendations:**
1. **Add a complexity/size lint gate** (ruff `C901` max-complexity or a file/function LOC check in CI) to catch god-files like `atp-dashboard/atp/dashboard/v2/routes/ui.py` before they reach 2900+ lines — and split it and `tournament/service.py` into per-domain route/service modules now, since every future PR touching dashboard UI routes currently risks merge conflicts in one file.
2. **Close the two known coverage gaps deliberately**: bring `atp-core/atp/cost/tracker.py` (22%) and `atp-core/atp/cost/models.py` (51%) up toward the package's ~90% baseline, and add dedicated `rbac/` permission-matrix tests in atp-dashboard (currently one file for 626 lines of access-control logic).
3. **Formalize atp-sdk's higher bar as the external-facing standard**: it's the one package strangers will actually `pip install`/`uv add` without monorepo context, and its retry/auth/error-handling discipline is a good template — extract a short "public package checklist" and apply it to any future externally-published package.
